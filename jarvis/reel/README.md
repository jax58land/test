# モーションリール「ヘイ、ジャービス！」

添付PDF（「ヘイ、ジャービス！」完全攻略マニュアル）の中身を伝える、27秒のモーションリール。
映像も音もすべてコードで作っている（Canvas 1枚＋Web Audioで合成。画像・動画・音の素材、生成AI、動画用フレームワークは不使用）。

## 中身

| ファイル | 役割 |
|---|---|
| `index.html` | リール本体（映像と音）。ブラウザで開くとループ再生。**画面をクリックすると音つきで頭から再生**（もう一度クリックで音なしに戻る） |
| `素材_記事.md` | 台本の元。PDFから事実だけを抜き出した要約。ここにない話はリールに入れていない |
| `export.mjs` | 書き出し用。Chromeで1コマずつ描いて撮り、音も合成して、ffmpegでMP4にする（puppeteer-core） |
| `out/完成.mp4` | 完成品。1920×1080 / 60fps / 27.10秒 / H.264 ＋ AAC 48kHz ステレオ（-15.6 LUFS） |
| `out/check/*.jpg` | 目視確認に使った途中のコマ（MP4から抜き出したもの） |

## 仕様

- 124BPM。1拍＝0.484秒。場面1〜8は各6拍、場面9は8拍で、計56拍（27.10秒）。場面の切り替えはすべて拍の頭
- どの場面も、**その場面を描いている関数自身のソースコード**（`sceneN.toString()`）が打たれて流れるところから始まる。そのコードの1文字1文字が粒になって飛び、形に組み上がる
- 拍ごとに画面がわずかに跳ねる。止まるのは最後の余韻（約0.5秒）だけ
- 書体はゴシック・明朝・等幅・ドット（Unifont）を混ぜている。Macでは ヒラギノ／Menlo、Linuxでは Noto CJK／IPA が使われる
- 明るい背景で、場面ごとに色を変えている。暗い紺と金は使っていない。ロゴ・タイムコード・章番号は描いていない

## 音（音楽と効果音）

すべて `index.html` の中で Web Audio を使って合成している（`makeSynth` / `scoreMusic` / `scoreSfx`）。素材ファイルはないので、著作権の心配がない。

- **音楽**：124BPMで映像の拍と同じ時刻に鳴る。場面ごとに和音を F → G → Em → Am → F → G → Am → G と進め、最後のタイトルで C に解決させる
  - 場面1：打鍵の音のあと、キックだけで立ち上がる
  - 場面2〜8：キック・手拍子・ハイハット・ベース・和音
  - 場面4からは16分のハイハット、場面5からはアルペジオを足して加速する
  - 場面9：一度引いて溜め、タイトルで大きく鳴らす
- **効果音**：映像の動きと同じ式・同じ時刻で鳴らしている

| 場面 | 効果音 |
|---|---|
| どの場面も | コードが打たれる打鍵音／場面の切り替わりでシンバル／組み上がった瞬間にベル |
| 1 | 渦の風切り音（左→右）／返事の1文字ごとにポン |
| 2 | 横・縦の2段のシュッ／打ち消し線のシャッ／札のポン |
| 3 | 吸い上げ音／落ちてくる粒の雨音（34粒） |
| 4 | 回転する風切り音（右→左）／渦の上昇音／時計のチクタク／STEPが開くポン |
| 5 | 波のうねり／待受中・接続中・話していますで上がっていく音 |
| 6 | 升目に収まるカチカチ／札が着地する瞬間のドン |
| 7 | 爆ぜる音／集まる上昇音／7項目の連打ポン |
| 8 | 押し固める吸い込み音／判子が着地する瞬間のドン（8回） |
| 9 | 沈む音・飛んでくる音／タイトルの一撃／帯が差し込む風切り音／チャイム |

- 音量は配信向けにそろえている（ffmpeg の loudnorm で -14 LUFS を目標、最大 -1.5 dBTP。結果は -15.6 LUFS / 最大 -1.2 dBFS）

## 書き出し方

```bash
cd jarvis/reel
npm install                      # puppeteer-core が入る
node export.mjs                  # 映像と音を作って out/完成.mp4 にする（このPCで約80秒）
node export.mjs --audio-only     # 映像は前回のものを使い、音だけ作り直して重ねる（数秒）
node export.mjs --stills 3,12,26 # 指定した秒のコマを out/frames/ にPNGで出す
```

Chromeは、`CHROME_PATH` か、Mac の `/Applications/Google Chrome.app/...` か、Linux の定番の場所から自動で探す。ffmpeg が必要。

## 確認したこと

- 途中のコマを3回に分けて計25枚以上書き出して目で見た。直したのは次の点
  - 組み上がった文字の上に芯の色をかぶせていてコードの粒が見えなかった → 芯の色を粒の下に回した
  - 飛んでいる途中の粒が小さすぎて、画面がほぼ空に見えた → 飛んでいる間は粒を大きく描くようにした
  - 場面3の途中で粒がすべて画面の外にいて、空白のコマになっていた → 落ち始めを早めた
  - 場面2で「1」と「行」が重なっていた／場面8で最後の札が項目に近すぎた → 位置を直した
- 「止まって見える時間」を数値で調べた。0.5秒離れた2コマを比べ、目に見えて変わった画素（明るさの差が10/255を超えるもの）の割合を全区間で測ったところ、最小でも2.4%が変化していた。最初は2か所が1%未満だったので、動きを足して直した

- 音は数値と図で確認した（私は音を聴けないため）
  - 音量と最大値を測った。音割れはない
  - 0.3秒以上の無音はない
  - スペクトログラムで、キックが拍に、シンバルが場面の切り替わりに、ベルが組み上がりに並んでいることを確かめた
  - 判子の「ドン」は、判子が縮んで着地するコマに合わせて0.05秒遅らせた
  - **音の好み（音色・バランス）は、実際に聴いて判断してください**
